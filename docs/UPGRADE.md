# 让 Agent 帮你升级

对你的 Agent 说：“帮我升级健身系统，保留记录、知识库和壁纸，检查核心页面后再替换。”

Agent 先检查官方发布版本与本地改动，使用确定的发布版本；不要覆盖用户自己改过的仓库。取得版本后，在仓库运行 `python tools/upgrade.py --root <用户系统目录> --platform codex --apply`。Claude 或其他 Agent 修改 platform；需要指定安装位置时传 `--agent-root`。不带 `--apply` 只检查。

升级复用现有官方界面迁移：备份原 HTML，保留原路径、实例身份、训练数据、知识正文与背景，手机/桌面导航检查通过后替换，替换后再检查，失败回滚。未知自定义界面停止自动覆盖，让 Agent 按差异保留自定义后修复。官方模板历史现支持到 v3.2.0。

Skill 安装与用户已生成的网页是两层，不能只更新仓库后就说网页已升级。第三方学习组件不随主体升级覆盖。新版本不会替你重新制定计划或将学习示例导入私人知识库。

无需复杂的迁移仪式；有重要本机记录时，先在原浏览器导出已有备份。HTML 备份不含 IndexedDB 照片及浏览器资料。升级不改数据库或浏览器存储，也不会自动部署网站。依赖 Node.js、Playwright 和 Chromium 才能运行界面检查，缺少时由 Agent 在独立验证目录准备，不能跳过后假称通过。

如果使用中出现问题，把页面、操作步骤和截图交给 Agent：“修复这个问题，保留我的记录，只改受影响部分，并检查手机/电脑。”已经准备的 HTML 备份可用于恢复；有后续编辑时先比较，不覆盖新内容。检查降低常见回归风险，不承诺所有设备无缺陷。

## 建档后立即同步

用户已提供个人信息和真实训练计划时，Agent 必须在同轮更新主源、执行基准及工作台数据并运行正式检查，不等待额外的刷新请求。真实计划、字段完整度和负荷校准分别处理；姓名代称含“匿名”或旧标题含“待建档”不能把真实计划误识别为示例。体重、经验或部分重量未知时局部留空或标待填写/待校准，已知动作、组次与重量仍保留。首次没有历史训练记录也不妨碍建档展示。

使用过程中取得新的个人事实、实际训练、体感或已确认计划后继续增量刷新；无需重新建一套系统，也不自动改写正式计划或部署网站。仅安装 Skill 而未刷新已生成 HTML 时，不能报告问题已经解决。
