# 离线记录与备份

## 训练

填写每个工作组的重量、次数与 RPE，并明确标记本次未做的动作，然后点击完成训练。本机模式不需要登录；只有数据库事务成功后才显示“已完成”。可以在训练日历中查看详情、纠正误填数值、查看周训练量或恢复最近一次修改前的记录。完成组与热身、未做动作区分统计，计划快照不被实际记录覆盖。

改变计划版本不会清空本地历史。不同系统实例的正式记录相互隔离。同一条记录被其他页面修改后，旧页面需要先刷新，不能直接覆盖新记录。

## 餐食与照片

1. 选择餐次，填写名称或说明；照片可选，一阶段最多 6 张。
2. 保存餐食到本机。照片与餐食元数据在同一个数据库事务中保存；失败时不会声称保存成功。
3. 根据食品标签、自己的估算或外部 AI 结果，填写热量与碳蛋脂，并注明来源。此时只是候选，不计入摄入合计。
4. 检查后单独确认入账；可以撤销确认，原候选仍保留。
5. 没吃完时，先保存饭后说明或照片，再填写实际吃下的候选并确认；餐前估算不会被覆盖，也不会自动按整餐比例推算实际摄入。

离线页面没有内置照片识别模型，不会把选中照片、保存照片或手动填写数值描述为“AI 已识别”。未填写的数值保持未知，不能被当成零。

## 备份范围与隐私

在“指南”选择“导出本地记录备份”，或在本机饮食页选择本地归档，下载 JSON 备份。范围是本机正式训练（含修订快照）、餐食及其照片；**不包含未完成训练草稿、云端数据，以及旧版体重、有氧、体感资料**。备份由浏览器保存到用户选定的下载位置，网页不能直接写入 Obsidian 或读取其他本地文件。

在另一个浏览器或迁移后页面的空本地记录库中选择“导入本地记录备份”。导入会检查格式和照片引用；非空记录库会拒绝导入，不静默覆盖或拼接现有数据。导入不会上传任何内容。

当前导入上限为单个文件 100 MB、最多 20000 条数据库条目（照片也算条目）。大量长期照片可能超过此限制；导出后先在独立空实例中试导入核对，不要在未验证恢复之前清除原浏览器数据。

备份含个人记录和照片，应保存在私人目录，不能加入 Git、公开 Release 或公开托管目录。

## 浏览器限制

- 使用支持 IndexedDB 的现代浏览器。本地双击 HTML 的 Chromium 流程有浏览器回归测试；其他浏览器需自行验证其本地文件存储策略。
- 数据属于当前浏览器和网页来源。无痕窗口、空间不足、清除站点数据、更换浏览器或移动文件，都可能影响可用性；迁移前先导出并核对备份。
- 数据库无法打开或写入失败时会提示失败，不把它当作空记录或成功保存。
- 旧版未带实例标识的训练草稿无法可靠判断归属，不会被自动混入新实例。升级前保留旧页面及浏览器数据，不要把新版本覆盖当作旧草稿已迁移。
- 已配置云端的页面与本机模式保持清晰边界。云端故障不会自动创建一份看似已同步的本地正式记录，本地备份也不会自动上传到账号。

## 可选 Agent

网页与安装器统一使用 `lzheng-fitness-agent://run`，只响应用户明确点击。安装器不自动运行任务；网页不传递命令、文件路径或配置。真实云端导出、模型调用和回写仍由仓库外的私有适配器提供，离线餐食保存不依赖它。
