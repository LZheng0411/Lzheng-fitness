# Lzheng Fitness v3 匿名开源系统升级方案

## 1. 目标

把当前项目从“训练计划与复盘 Skill 工具箱”升级为“可以生成完整个人健身系统的匿名开源母体”。

陌生用户应能在没有原作者 Vault、训练记录、账号、云环境和本机路径的情况下，构建出与原系统同构的闭环：

```text
建档 → 计划 → 今日训练 → 逐组记录 → 训练复盘 → 用户确认调整
                    ↓
              有氧记录 / 饮食目标
                    ↓
       餐食照片估算 → 饭后校正 → 用户确认 → 周复盘
```

“同构”指功能职责、交互流程、数据边界、升级方式和验收标准一致；不复制原作者的姓名、训练处方、重量、复盘、照片、账号、Notion 地址、云环境或电脑路径。

## 2. 本轮边界

### 必须完成

1. 保留并兼容现有能力，并把独立营养契约扩展为第 8 个 Skill。
2. 将训练记录器泛化进入匿名工作台模板：
   - 按当前计划生成完整动作列表；
   - 点击动作进入记录卡；
   - 支持多个重量段；
   - 逐组记录次数与 RPE；
   - 支持“本次调整”“本次未做”和动作问题记录；
   - 计划快照与实际执行分开保存。
3. 加入有氧记录模块：爬楼、跑步、游泳、自定义；本地保存为默认能力。
4. 加入饮食最小闭环：
   - 训练日类型映射到宏量目标；
   - 多张餐前照片；
   - 餐前估算和饭后实际摄入候选分开；
   - 未经用户确认不得计入实际摄入；
   - 周复盘只能在满足数据门槛后生成候选调整。
5. 提供可选 CloudBase 自托管适配器：公开数据库迁移、owner-only RLS、匿名配置示例、安装说明和诊断脚本。
6. 提供本地按需 Agent：真实任务存在且用户明确运行时只处理一轮；默认不自启动、不常驻、不定时查询。
7. 更新安装器、README、新手指南、CHANGELOG、manifest 和整包验证。
8. 在全新隔离目录完成初始化、页面检查、移动改名回归、匿名发布副本和隐私扫描。

### 本轮不做

1. 不修改或复制原作者个人训练项目、Vault、Notion 和 CloudBase 数据。
2. 不上传或部署个人工作台，不发布包含个人数据的 Release；匿名源码通过隐私闸门后允许提交、合并并推送 `main`。
3. 不把真实手机号写入、跨设备回读或真实照片识别描述成已验收；只能交付可复现的本地/模拟测试和待用户执行的真实验收步骤。
4. 不把“网页创建任务”描述成“已经唤醒本机 Agent”。静态网页不能凭空启动本机进程。
5. 不恢复旧的每两分钟轮询、登录触发器、隐藏常驻 Worker 或任何网页后台任务轮询。
6. 不为四个力量主项写死训练模板；非力量目标必须继续可用。

## 3. 架构

### 3.1 四层边界

| 层 | 内容 | 开源状态 |
| --- | --- | --- |
| 系统内核 | Skill、构建器、检查器、升级器、工作台模板 | 开源 |
| 功能模块 | 训练记录、有氧、饮食、Agent 任务契约 | 开源 |
| 基础设施适配器 | 本地存储、CloudBase 迁移与本地 Agent | 开源、默认关闭云端 |
| 用户实例 | 计划、复盘、训练记录、照片、账号、密钥、私有配置 | 仓库外私有 |

### 3.2 默认运行模式

- `local`：默认。页面可离线打开；训练、有氧和饮食草稿保存在当前浏览器本地；无登录、无网络请求、无 Agent 后台任务。
- `sync`：用户显式配置 CloudBase 后启用；数据库按账号 owner-only 隔离；云端失败时保留本地事实和“待同步”状态。
- `agent`：在 `sync` 基础上由用户显式运行一次本地 Agent；结果只写成候选，用户确认后才进入正式记录。

缺少云端配置时必须安全降级到 `local`，不能白屏、重复登录、暴露内部错误或持续重试。

### 3.3 配置契约

公共模板不得硬编码云环境、域名、手机号、Token 或磁盘路径。新增匿名配置示例，至少包含：

```json
{
  "schema": 1,
  "mode": "local",
  "cloudbase": {
    "enabled": false,
    "endpoint": "",
    "env_id": "",
    "auth_mode": "phone_otp"
  },
  "agent": {
    "enabled": false,
    "mode": "manual-on-demand-once"
  }
}
```

客户端可公开标识与真正密钥必须分开。后台凭证只能存在于仓库外的私有适配器目录；安装器和升级器不得覆盖该目录。

## 4. 建议目录

在不破坏现有 Skill 主结构的前提下增加：

```text
integrations/
└── cloudbase/
    ├── README.md
    ├── migrations/
    ├── local-agent/
    └── examples/
        └── cloudbase-config.example.json
```

工作台仍只有一个源模板：

```text
skills/lzheng-fitness-workbench-builder/assets/workbench-template.html
```

不得新增第二套正式页面壳。训练、有氧和饮食 UI 必须进入该脱敏模板，并由同一构建器生成用户实例。

## 5. 数据边界

### 5.1 训练记录

- `training_sessions`：一次训练及计划版本快照。
- `training_exercises`：计划动作、实际动作、跳过/替换原因、问题记录。
- `training_sets`：逐组重量、次数、RPE；是实际执行的明细真源。
- `training_agent_jobs`：只保存需要 Agent 复盘的任务状态，不代表任务已经处理。

同一稳定记录不得因当前计划升级而改写；已经开始的训练继续使用开始时的计划快照。

### 5.2 有氧记录

- 支持同一天多条记录；
- 本地优先保存；
- 云端以 UUID 幂等合并；
- 未同步不得显示成已跨设备同步。

### 5.3 饮食记录

- `estimate` 永远表示上桌食物估算；
- `consumed_estimate` 表示饭后证据形成的实际摄入候选；
- `confirmed_nutrition` 只有用户确认后才可写入；
- 图片属于私人对象，不得进入公开发布目录；
- 低置信度和范围必须保留，禁止伪造精确克数。

## 6. 额度安全契约

这部分是发布阻断条件，不是建议。

### 6.1 本地 Agent

- 默认模式固定为 `manual-on-demand-once`；
- 安装后计划任务必须为 Disabled、0 个自动触发器；
- 安装器不得访问真实队列或自动启动 Worker；
- 空队列只查询一次并立即退出，不调用模型；
- 同一任务必须幂等领取，禁止重复识别；
- 可选 `-Watch` 仅用于临时排障：最长 10 分钟、连续 3 次空队列停止、连续 3 次失败熔断。

### 6.2 网页

- 只允许用户显式点击刷新后读取一个已知任务；
- 每次操作只读一次，不设置 interval、timeout 或页面可见性监听；
- 无任务、失败或未知状态都立即返回；
- 有登录 session 但数据库不可用时不得重复弹出验证码。

### 6.3 自动验收

新增静态与模拟安全测试，至少阻断：

- 登录或定时自动触发器；
- 无限循环查询队列；
- 两分钟或其他后台周期空查；
- 页面无任务时启动轮询；
- 任意后台轮询或定时再次读取；
- 同一任务重复调用 Agent；
- 空队列调用模型；
- 私人照片进入发布包。

## 7. 隐私与脱敏

验证器必须扫描全部文本和发布文件，拒绝：

- Windows 绝对路径、`file://`、`obsidian://`；
- 原作者姓名、私人品牌称呼、手机号、邮箱；
- Notion 页面/数据库 ID；
- CloudBase 真实环境 ID、真实域名和后台凭证；
- 真实训练日期、重量、RPE、体重、围度、复盘正文；
- 私人图片对象键和临时任务 ID。

匿名示例可以展示字段和流程，但不得冒充训练处方。初始化页面必须保持“待建档”，示例重量不进入正式今日处方。

## 8. 实施顺序

1. **保护基线**：记录当前 `git status` 和 diff；不得 reset、checkout、clean 或覆盖现有未提交改动。
2. **模板泛化**：从已经脱敏的运行模板提取训练、有氧和饮食界面；移除环境专属配置；合回唯一公开模板。
3. **本地优先**：先保证无云配置时训练、有氧和饮食均能安全打开和保存草稿。
4. **CloudBase 适配器**：迁入通用迁移、owner-only RLS、匿名配置和说明；禁止携带真实环境状态。
5. **按需 Agent**：迁入最小必要脚本和 Schema；删除或封死历史常驻模式；加入安全测试。
6. **构建链**：让初始化、刷新、发布准备、检查器和升级器保留新模块，不覆盖用户事实。
7. **文档与版本**：更新 README、新手指南、Skill、CHANGELOG、manifest；明确三种模式及真实验收边界。
8. **隔离验收**：运行完整测试，并在新空目录 bootstrap；移动改名后再次检查；生成 public-anonymized 副本并扫描。
