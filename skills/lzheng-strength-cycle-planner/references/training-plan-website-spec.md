# 训练计划网页规范

为力量周期规划交付可直接打开的本地 HTML。网页是训练处方的可视化副本，不是展示用的虚构样例。页面必须由 `../assets/strength-cycle-template.html` 生成，AI 只提供周期 JSON，不得手写另一套 HTML、导航或视觉主题。

## 1. 数据核验

在写 HTML 前建立如下信息：

| 类别 | 必须准确的字段 |
| --- | --- |
| 使用者与周期 | 使用者标识（若提供）、生成日期、计划周数、适用日期 |
| 身体与限制 | 当前体重、伤痛/限制、动作标准、器械、最小加重单位 |
| 训练安排 | 每周频率、每个训练日顺序、主项职责、辅助动作 |
| 主项起点 | 最近日期、动作、重量、组次、RPE/RIR、动作质量、数据来源 |
| 周期目标 | 测试项目、目标表现、是否测 1RM、减量和复盘节点 |

优先使用用户本次明确提供的数据；用户授权且环境可访问外部训练记录时，再查询当前周期和最近动作记录。只采纳与该动作关系一致的记录。把器械下拉、哑铃单腿硬拉等错误归类的行排除在杠铃主项依据之外。若用户明确以某次记录为准，保留该选择和日期。缺失、冲突或估算必须在页面写明，不得假装已核验。

## 2. 页面内容

页面至少包含以下区块，并提供锚点导航：

1. 页头：计划名称、周期定位、简短目标；
2. 基本信息：已核验基准、频率、周期长度、限制；
3. 每周安排：训练日与职责；
4. 上肢/下肢或用户实际训练日：动作、组次、RPE、休息；
5. 每个主项的完整 8—12 周周期表；
6. 热身、进阶、未完成/退行、减量和复盘规则。

多主项必须分别展示其周期；低频硬拉等动作按实际暴露次数标注。辅助动作可以因使用者的器械、目标、恢复和偏好变化，但不得挤占主项质量。

网页中的 RPE 是处方的一部分：每个包含 2 组及以上正式工作组的单元格必须直接写为“首组 RPE→末组 RPE”，例如 `4×6 @6→7`。不要在表内保留 `4×6 @7`、`3×8 @7—8` 一类静态写法，再依赖页面注释解释；只有单组顶组、测试尝试和明确标注为历史实际记录的内容可以不使用箭头格式。

## 3. 视觉语言

采用简洁的“纸面高级感”：白底、浅灰信息块、深色文字和单一深绿强调色。仅警告信息可使用低饱和橙色。概览默认使用一张完整的圆角“计划参数”卡，包含基准段落和等宽指标；不要使用未填满的通用栅格卡片或留下灰色空单元格。每周安排使用三列表格；每个实际训练日使用独立动作表卡片，清楚列出动作、组次、目标和休息。

- 使用白/浅灰底、细分隔线、充足留白；不要渐变、多色标签、厚重卡片或装饰性仪表盘。
- 页头默认必须在右侧放置 `assets/header-lineart.png` 的人物线稿；将标题保持在左侧。移动端隐藏线稿。除非用户明确要求不同风格，否则不得替换为其他图片或省略。
- 用 `counter` 为主要区块生成 01、02 等编号；让标题、关键数字和表格承担层级。
- 表格只保留行间细线；长周期表允许横向滚动。禁止把长句塞进窄的三列表格；交替方案改为并列信息块，手机端转单列。
- 使用 `scroll-margin-top` 防止粘性导航遮住锚点标题；提供打印样式，隐藏粘性与装饰图。

## 4. 主项渐进曲线

除非用户明确只要文字或拒绝网页，每个主项周期表前必须生成一张“强度 + 容量”图。图表是当次计划数据的可视化，不是装饰图；具体结构、JSON 输入、容量口径和曲线算法以 [周期 HTML 与曲线契约](cycle-html-contract.md) 为准。

- 图表置于该主项 `<h3>` 与周期表之间；一个主项只保留一张当前版本图表。
- 强度左轴、容量右轴，阶段带、图例、脚注与数据标签必须完整；轴刻度按当前数据生成，不沿用其他计划的刻度或坐标。
- 使用 Fritsch–Carlson 单调三次插值，不得以任意平滑曲线制造不存在的峰值或谷值；低频动作只呈现实际暴露数据。
- 强度、容量、测试周和自重/归零周的显示必须能追溯到表格的本次处方，容量计算口径写入图内脚注。

## 5. 实现和验收

- 用户指定输出目录时优先使用；否则先使用已初始化系统配置中的 `output_locations.cycles`，尚未建立系统配置时才使用 `LZHENG_FITNESS_HOME/plans/` 或当前工作目录的 `lzheng-fitness-output/plans/`。新文件采用 `YYYY年MM月DD日-训练对象-周期目标训练计划.html`：单项以动作名为训练对象，整套计划以训练结构为训练对象；日期按当前用户时区的首次制定日、月日补零。实质修订保留原日期并添加 `-v02`、`-v03`，新周期才使用新的制定日期；禁止覆盖旧文件或使用“最新版”“最终版”等命名。
- 使用单个 UTF-8 HTML 文件和内嵌 CSS；不要依赖 CDN、框架或网络字体。
- 为保证上传到其他环境后图片仍显示，默认运行 `scripts/inline_html_image.py <html> --asset <skill assets/header-lineart.png>`，把线稿转为 HTML 内部的 `data:image/...;base64`。不要依赖同目录相对路径，也不要使用会过期的临时外链。
- 在宽屏和小屏检查：标题不被图遮挡、卡片不溢出、表格可读、长表可滚动、中文不会逐字挤压。390px 视口必须满足 `document.documentElement.scrollWidth <= clientWidth`；长表和图表只允许在自身容器内横向滚动。
- 用页面内容逐项对照最终文字计划，检查动作名称、重量单位、RPE、周次和基本信息。
- 用全文检索检查网页的多组 RPE：排除单组顶组、测试尝试和历史实际记录后，不得存在静态 RPE 处方；文字计划、HTML 页面和执行基准必须一致。
- 使用 `scripts/render_strength_cycle_html.py` 从当次 JSON 数据生成；默认新建版本，拒绝覆盖已有计划。已有页面只在需要补嵌页头时使用 `inline_html_image.py`。
- 检查每张图只出现一次、没有 `<polyline>`、没有网络资源；在窄屏和打印预览中确认图表、表格和中文脚注可读。
