# 周期规划 HTML 与渐进曲线契约

本契约固定的是交付形式，不固定某一次计划的动作、重量、周数或测试目标。所有网页和文字计划必须来自同一份当次计划数据，并由唯一模板 `../assets/strength-cycle-template.html` 渲染。跨页面职责见 `../../lzheng-training-system/references/html-template-contract.md`。

## 固定页面框架

按以下顺序输出单文件 UTF-8 HTML：

1. 左标题、右线稿的页头：计划名称、周期定位、简短目标；移动端隐藏线稿。
2. 锚点导航固定为：概览、周结构、训练日、周期、规则。
3. 概览：一张完整的“计划参数”卡，包含已核验基准、周期长度、频率、限制与待核验项；不使用未填满的通用网格或灰色空单元格。
4. 每周安排：先以三列表格呈现建议日程、训练主题与主项职责，再以各训练日独立动作表呈现动作、组次、RPE 与休息。
5. 主项周期：每个主项依次输出标题、渐进曲线、完整周期表。
6. 规则：热身、进阶、未完成分支、减量、测试和复盘。

页面必须白/浅灰底、细分隔线、深色正文和单一深绿页面强调色；不使用 CDN、网络字体、脚本、渐变、仪表盘或装饰性多色卡片。长表横向滚动，窄屏不逐字挤压；提供打印样式。

## 图表固定形式

- 每个主项恰好一张图，置于该动作 `<h3>` 与周期表之间。
- SVG 统一使用 `viewBox="0 0 1040 344"`；强度为左轴、容量为右轴。
- 强度使用墨色 `#1f2937`（面积填充和实心数据点），容量使用灰色 `#98a2ad`（细线和空心点）；计划性自重/归零点使用 `#a3a3a1`。
- 图表必须含标题、说明、图例、阶段背景带、坐标刻度、数据标签与容量口径脚注；文字应继承页面字体。
- 阶段背景带由当次阶段数据生成；不得假定任何固定的 8 周、10 周或 12 周结构。
- 低频动作只绘制实际有效暴露的数据点。空周不可伪造成完成数据；如需跨周连接，说明“仅暴露周有数据”。
- 强度和容量按本次数据独立缩放。容量默认从 0 起；强度刻度须留出可读边距。
- 曲线使用 Fritsch–Carlson 单调三次插值。每一段不得越出端点高度范围，峰值与谷值必须是实际数据点。禁止复制其他计划的 SVG `path` 坐标、重新手改坐标或用平滑曲线伪造表现。

## 数据契约

生成器读取 JSON。最小结构如下；所有数值均是当前计划数据，不得由历史样例补齐：

```json
{
  "plan": {
    "title": "2026年08月02日-四日制-力量提升训练计划",
    "subtitle": "8 周验证周期",
    "weeks": 8,
    "athlete": "示例训练者",
    "goal": "各主项按计划完成并在 W8 验证",
    "frequency": "每周 4 练",
    "constraints": "无已知疼痛；重量待每次 RPE 校准"
  },
  "phases": [
    {"label": "积累", "start_week": 1, "end_week": 3},
    {"label": "减量", "start_week": 4, "end_week": 4}
  ],
  "schedule": [{"day": "上肢 A", "role": "卧推强度", "detail": "主项优先"}],
  "cycles": [
    {
      "id": "bench",
      "title": "卧推：每周强度＋容量",
      "headers": ["周次 / 阶段", "强度职责", "容量职责", "完成标准"],
      "rows": [["W1 积累", "62.5kg×6 @7", "50kg 4×8 @6→7", "动作标准完整"]],
      "chart": {
        "strength_label": "强度（kg）",
        "volume_label": "容量（kg）",
        "strength": [{"week": 1, "value": 62.5, "label": "62.5"}],
        "volume": [{"week": 1, "load": 50, "sets": 4, "reps": 8, "label": "1600"}],
        "footnote": "容量 = 容量职责日重量 × 组数 × 次数"
      }
    }
  ],
  "rules": [{"title": "进阶", "body": "达到目标且 RPE 不超标时推进。"}]
}
```

`volume` 点可直接提供 `value`，或提供 `load × sets × reps` 由生成器计算。`label` 可用于显示“自重”“测试”等业务标签；若某点是计划性自重/归零，使用 `"kind": "bodyweight"`。周期表中的多组正式处方仍必须直接写 `首组 RPE→末组 RPE`。

## 生成与验收

1. 先把最终文字计划整理成上述数据，明确“已核验 / 用户提供 / 待核验”。
2. 使用 `scripts/render_strength_cycle_html.py` 生成新版本 HTML；不要编辑既有 HTML 覆盖旧版本。
3. 对照文字计划检查标题、动作、重量、组次、RPE、周次、容量口径和图表点。
4. 检查每图仅一份、没有 `<polyline>`、没有外链，且页面在窄屏和打印时可读。
5. 有数据缺失时在页面标“待核验”，不要编造曲线、容量或精确公斤数。
