# 路径可迁移修复协议

本文件是 AI 处理 Lzheng Fitness 路径、链接、跨电脑迁移和发布副本问题时的执行真源。它不是面向用户的提示词，也不是只读诊断清单。出现链接打不开、移动后失效、`Vault not found`、素材缺失、系统命令继续访问旧目录或发布检查假通过时，AI 必须按本协议完成审计、修复和回归验证。

## 一、完成定义

只有同时满足以下条件，才能说“路径问题已修复”：

1. 使用者复制完整系统目录后，可以直接打开工作台并使用主要入口。
2. 更换盘符、父目录、系统文件夹名称或电脑用户名后，不需要手工修改路径。
3. 完整计划、复盘、复盘索引和状态档案都能读取；Obsidian 只能是可选编辑入口。
4. `doctor`、`upgrade`、`validate`、`process-handoffs` 和工作台刷新在移动后仍指向当前系统。
5. 页面引用的图片、视频、海报和其他本地资源都在迁移边界内。
6. 发布副本没有指向未复制文件的按钮。
7. 旧版绝对路径可以安全迁移，用户计划、复盘、状态档案和私人知识包不被覆盖。
8. 自动检查实际覆盖所有入口和运行命令，不以“字段存在”代替“能够打开”。

## 二、迁移边界

默认迁移单位是初始化生成的完整系统根目录，而不是单独的 `健身工作台.html`。系统根目录至少包含：

- `个人训练系统/`；
- `健身知识库/`；
- `系统/lzheng-system.json`；
- 系统托管模板和索引。

Skill 代码安装在当前 Agent 的 Skill 目录中，不要求与用户系统一起复制。运行时应使用当前正在执行的 Skill 位置，不能继续信任旧电脑保存的 Skill 绝对路径。

如果用户只复制了一个 HTML 或漏掉目录，页面和检查器必须指出具体缺失项，不能静默失败。

## 三、保护边界

修复路径时禁止：

- 修改训练处方、动作、重量、组次、RPE/RIR 或周期内容；
- 覆盖、删除或批量移动用户计划、复盘、状态档案和私人知识包；
- 用旧模板覆盖当前最新前端；
- 把个人数据、账号、用户名、原 vault 名或本机路径写入公开包；
- 只修一个截图中的按钮就宣称整套系统可迁移；
- 未经用户授权推送、合并、部署或发布 Release。

先在独立分支或副本中工作。发现已有用户修改时保留并绕开；无法安全绕开时停止写入并报告冲突。

## 四、路径清单

开始修改前，枚举并分类所有路径来源。至少检查：

### 页面入口

- 完整训练计划；
- 单次训练复盘；
- 复盘索引；
- 状态档案；
- 图表中的复盘点；
- Notion 外部入口；
- 图片、视频、海报和背景；
- 页面导航与锚点；
- 可选的 Obsidian 编辑入口。

### 页面实现

- HTML `href`、`src`；
- CSS `url()`；
- `<img>`、`<video>`、`<source>`；
- JavaScript 动态跳转和 `window.location`；
- `workbench-data` 中所有 `_path`、`_file`、`_href` 和 `source` 字段；
- URL 编码、解码和特殊字符处理。

### 系统与脚本

- `project_root`；
- `skills_root`；
- `backup_root`；
- `output_locations`；
- Notion 输入、备份、交接记录和发布目录；
- 安装器、初始化器、构建器、检查器和迁移脚本。

### 需要识别的风险

- 固定盘符和用户目录；
- 固定 vault 名；
- 保存好的绝对 Obsidian 深链；
- `file` URI；
- 越出系统根目录的 `..`；
- UNC 或网络共享；
- 中文、空格、括号、井号、百分号和问号；
- Windows 与 macOS/Linux 路径分隔符和大小写差异；
- 页面从本地文件打开与通过本地服务打开的差异。

审计结果按“代码位置、当前形式、失败条件、用户影响、修复方式、验证方式”记录。未经实际验证的判断标记为待验证。

## 五、统一存储规则

### 可以持久化

- 以系统根目录或个人训练系统根目录为基准的相对路径；
- 文件用途标识，例如 `current_plan`、`review_index`、`status_index`；
- 经过 URL 编码的项目内相对浏览器链接；
- 用户明确配置的 `http` 或 `https` 外部链接。

### 不得持久化

- 生成电脑的盘符和绝对路径；
- Windows 用户名或用户目录；
- macOS/Linux 私人 home 路径；
- 固定 Obsidian vault 名；
- 已绑定旧电脑位置的 Obsidian 深链；
- 指向项目外部的浏览器链接；
- 仅在生成时存在的临时目录和发布目录。

绝对路径只允许作为一次运行过程中的内存值，用于读取、校验和写入目标文件；不能进入可迁移配置、HTML 数据块、公开模板或发布副本。

## 六、路径解析规则

### 系统根目录

按以下顺序确定：

1. 用户本次明确指定的目录；
2. 当前命令的 `--root` 或 `--project`；
3. 当前系统配置文件所在目录；
4. 明确设置的 `LZHENG_FITNESS_HOME`；
5. 都不可用时停止，不猜盘符。

配置中的相对路径必须相对于当前系统根目录解析。旧配置中的绝对路径如果不属于当前根目录，即使旧地址在本机仍然存在，也不能优先于当前根目录中的真实文件。

### Skill 根目录

优先使用当前正在运行的 `lzheng-training-system` 所在 Skill 集合。旧配置里的 `skills_root` 只能作为兼容输入；它与当前运行位置冲突时，以当前运行位置为准。

### 备份目录

默认根据当前系统根目录重新计算。旧 `backup_root` 指向其他电脑或其他系统时，不得在那里创建新备份。迁移配置前先把原配置备份到当前系统可控的备份位置。

### 项目内目标

解析相对目标后必须确认：

1. 目标位于允许的迁移边界内；
2. 不发生目录穿越；
3. 文件类型符合入口职责；
4. 目标真实存在；
5. 页面展示的入口和检查器验证的是同一个目标。

## 七、打开行为契约

### 完整训练计划

- 继续使用现有计划 HTML；
- 工作台存储 URL 编码后的相对链接；
- 点击后由浏览器直接打开；
- 用户不接触、不复制、不填写路径；
- 移动完整目录后不需要重新生成链接。

### 训练复盘和状态档案

- Markdown 文件仍是唯一主源；
- 默认在工作台内部直接阅读，不批量生成独立 HTML；
- 工作台数据只保存相对文件标识和必要的可读内容；
- 如提供“在 Obsidian 编辑”，必须根据当前页面位置即时生成；
- Obsidian 未安装、vault 未注册或目录不在 vault 中时，主要阅读功能仍可用。

嵌入 Markdown 内容时必须防止内容提前闭合 HTML `script` 数据块。生成 JSON 时转义危险的结束标签，并在页面端先转义再渲染，不能直接信任 Markdown 中的 HTML。

### 图表复盘点

图表点与复盘卡必须使用同一个复盘目标。检查器要验证每个可点击图表点对应的复盘真实存在，不能只检查最近五条复盘卡。

### 外部链接

Notion 等外部链接必须明确标记为联网功能。断网或未配置时显示状态，不影响工作台、计划和本地复盘。

### 素材

所有本地素材使用项目内相对路径。检查器必须覆盖 CSS 背景、图片、视频、`source`、海报和降级素材；视频缺失或不能播放时使用静态海报，不让页面空白。

## 八、旧路径迁移

发现旧配置或旧 `workbench-data` 时按以下顺序处理：

1. 识别配置 schema 和旧路径字段；
2. 只读确认当前系统根目录及真实文件；
3. 在当前系统外的安全备份目录保存原配置或原 HTML；
4. 将可确认目标改写为相对路径或用途标识；
5. 删除旧盘符、用户名、固定 vault 名和保存好的本机深链；
6. 无法确认的目标标记为缺失，不猜文件；
7. 重新生成数据块并运行完整检查；
8. 移动整个系统到另一目录后再验证一次。

迁移只修改系统托管配置、模板引用和生成数据；不得修改训练正文。迁移失败时保留原件并给出恢复位置。

## 九、发布副本

发布准备程序必须先明确发布范围：

- 如果发布副本允许携带复盘和状态内容，就复制或安全嵌入实际需要的内容；
- 如果分享版不允许携带私人内容，就移除对应入口并明确显示“分享版不包含本地复盘”；
- 不允许保留目标未复制、点击必然失败的按钮。

发布检查必须基于最终目录，而不是源项目。它需要：

1. 枚举最终页面的全部可点击入口；
2. 解析动态生成的目标；
3. 检查计划和所有声明携带的文档；
4. 检查图片、视频、海报和降级素材；
5. 扫描盘符、私人 home、用户名、vault 名和绝对深链；
6. 确认模板与当前正式前端一致；
7. 缺少任何主要目标时返回失败退出码。

## 十、用户可理解的失败提示

禁止只显示“打不开”或让按钮无反应。按缺失目标提示：

- 没有找到训练计划：请复制完整健身系统目录；
- 没有找到复盘：指出缺失的复盘文件名；
- 状态档案缺失：说明工作台仍可查看计划，但状态信息不可用；
- 图片或视频缺失：指出素材名并启用静态降级；
- 配置仍指向旧系统：显示当前根目录和需要迁移的配置字段；
- 目录不是完整系统根目录：列出缺失的固定入口。

不要把内部绝对路径作为面向普通用户的主要提示；详细路径只放在诊断信息中。

## 十一、回归矩阵

每次路径修复至少执行：

### 初始化

- 在全新空目录初始化匿名系统；
- 页面、计划、复盘索引、状态索引和素材均存在；
- 匿名数据不作为正式处方。

### 整体移动

- 在含中文和空格的目录初始化；
- 移动到不同父目录并修改系统文件夹名称；
- 不重新生成链接，检查所有入口；
- 运行 `doctor`、工作台检查和交接 dry-run。

### 特殊字符

对空格、中文、括号、井号、百分号和长文件名进行 URL 编码回归。目标解析后必须仍在迁移边界内。

### 无 Obsidian

- 不启动 Obsidian；
- 计划、复盘和状态内容仍可读取；
- 可选编辑入口不可用时不得破坏主流程。

### 缺失文件

在隔离副本中分别缺少计划、单条复盘、索引、图片、视频时，检查器必须失败且指出准确目标。

### 发布副本

- 生成最终发布目录；
- 对最终目录运行检查；
- 确认所有显示的入口都有实际内容；
- 确认没有本机路径和私人数据。

### 旧版本

- 准备包含旧绝对路径的匿名旧版样例；
- 运行迁移并验证备份；
- 确认用户正文哈希不变；
- 再次移动后运行完整检查。

## 十二、强制验证

现有命令只是基础闸门，路径修复不得只运行其中一个：

```powershell
python "<skill>/scripts/Validate-FitnessWorkbenchSkill.py" --skill "<skill>"
python "<skill>/scripts/Test-FitnessWorkbenchPortability.py"
python "<skill>/scripts/Test-FitnessWorkbenchWeekTransition.py"
python "<skill>/scripts/Check-FitnessWorkbench.py" --project "<项目根目录>"
python "<repo>/tools/validate_bundle.py"
```

应扩展迁移测试，使它覆盖：

- 系统总控配置；
- `doctor`；
- 复盘和状态阅读；
- 图表复盘点；
- 发布目录；
- 图片、视频和海报；
- 缺失文件失败分支；
- 旧路径自动迁移。

测试输出 PASS 之前必须确认用户实际会点击的入口，而不是只确认数据字段存在。

## 十三、当前主要代码位置

AI 修改前重新读取当前代码，不依赖旧行号：

- 系统配置与命令：`../lzheng-training-system/scripts/lzheng_training_system.py`；
- 系统契约：`../lzheng-training-system/references/system-contract.md`；
- 工作台初始化：`scripts/Initialize-FitnessWorkbench.py`；
- 数据与路径生成：`scripts/Build-FitnessWorkbenchData.py`；
- 页面入口：`assets/workbench-template.html`；
- 发布准备：`scripts/Prepare-FitnessWorkbenchRelease.py`；
- 正式检查：`scripts/Check-FitnessWorkbench.py`；
- 迁移回归：`scripts/Test-FitnessWorkbenchPortability.py`；
- Skill 完整性：`scripts/Validate-FitnessWorkbenchSkill.py`；
- 整包验证：仓库 `tools/validate_bundle.py`。

如果项目结构已变化，先按文件职责重新定位，不照搬旧路径。

## 十四、交付报告

修复完成后报告：

1. 根因及影响入口；
2. 修改文件；
3. 新旧路径规则；
4. 旧系统迁移结果与备份位置；
5. 移动前后测试目录；
6. 每个主要入口的结果；
7. 系统命令结果；
8. 发布副本文件和入口结果；
9. 隐私扫描；
10. 尚未验证的范围。

严格区分“本地修复”“本地迁移验证”“发布副本验证”“已推送 GitHub”“已发布 Release”。没有执行的状态不得写成已完成。
