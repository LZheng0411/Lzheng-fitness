# 工作台界面升级

更新 Skill、刷新数据与升级用户已经生成的 HTML 是三件不同的事。日常刷新继续只替换 `workbench-data`。本流程只更换已识别的界面壳，不重新生成计划、复盘、营养事实或实例 ID。

## 用户入口与运行环境

用户只需说：“检查并修复我的工作台侧栏，保留我的记录和壁纸。”Agent 先明确当前运行 Skill 的位置与正式 HTML 路径，不将更新仓库等同于安装完成，也不寻找另一份页面替代用户原页。

先进行只读检查，再在用户已授权界面升级时执行：

```powershell
python "<系统 Skill>/scripts/lzheng_training_system.py" upgrade-workbench-ui --root "<系统根目录>" --check-only
python "<系统 Skill>/scripts/lzheng_training_system.py" upgrade-workbench-ui --root "<系统根目录>" --apply
```

只有训练项目而没有系统配置时，可以直接调用：

```powershell
python "<工作台 Skill>/scripts/Upgrade-FitnessWorkbenchUi.py" --project "<训练项目>" --backup-dir "<项目外备份目录>" --apply
```

默认行为是检查。实际升级必须运行浏览器验证，因此需要 Node.js、Playwright 与其 Chromium；缺失时明确失败并保留原页。开发仓库中使用 `npm ci` 和 `npx playwright install chromium` 准备环境。独立安装的 Skill 可从已经准备好 Playwright 的验证目录运行命令，或者使用 `NODE_PATH` 指向该目录的 `node_modules`。不应把验证依赖装进用户正式训练项目。普通建档、数据刷新与只读界面检查仍只需 Python。

## 状态与兼容边界

- `current`：当前文件的受管界面与运行模板一致；不是线上状态，也不代表训练事实已刷新。
- `needs_ui_upgrade`：识别为历史官方模板或受支持的导航缺失，可以准备候选。
- `unknown_or_customized`：存在未知界面改动，返回旧/新指纹及界面行差异范围，不写文件。应先审阅用户自定义、明确保留方案，再单独迁移；没有强制覆盖开关。
- `ui_upgrade_prepared`：候选兼容且数据保留检查通过；尚未替换，也尚未完成浏览器验证。
- `ui_upgraded`：候选及同路径替换后的浏览器验证都通过，回执记录原文件备份、前后文件哈希、数据块哈希和界面版本。

历史识别基于官方 v2.3.0、v2.3.1、v3.1.0、v3.1.1 模板的规范化指纹。自动流程仅接受 schema 6；旧 schema、缺失或无法解析的数据须先在独立流程处理。测试使用真实官方模板加匿名 schema 6 数据，不据此宣称所有历史用户数据都兼容。

受管差异仅包括标题、品牌、六个背景变量及视频块；普通 CSS、业务脚本或自定义导航不会被静默丢弃。背景文件必须已存在于项目内。未改其他代码而仅缺失或清空导航容器的页面可以修复。

## 保留与恢复

1. 检查路径边界、软链接和重解析点，拒绝项目内或与项目重叠的备份位置。
2. 原样保留数据块文本，包括 `system.instance_id` 与集成配置；保留受管标题、品牌、壁纸和取景。
3. 使用同目录临时候选验证相对资源与手机、桌面导航，验证浏览器采用独立上下文并阻止 HTTP(S) 网络访问。
4. 使用升级锁，替换前检查原文件没有被其他进程修改；备份后逐字节回读，再原子替换。
5. 在原绝对路径再次验证；失败恢复原页。替换后若出现第三方并发编辑，则保留编辑后的页面并明确告知原页备份位置，避免回滚覆盖新编辑。
6. 临时候选与本轮锁在结束时清理。进程被强制终止后可能留下锁；应先确认没有升级进程、核对备份与原文件，再由 Agent 清理，不能直接重跑覆盖。

**HTML 备份不包含浏览器数据库。** 升级不迁移、不改写数据库，但也不能把独立验证浏览器当成用户正在使用的浏览器。升级前建议从原浏览器导出私人记录备份，尤其是训练、餐食及照片；旧版体重、有氧和体感等 localStorage 资料不在现有导出范围内。保留原路径、浏览器用户配置和实例 ID，升级后在原浏览器核对记录。回执始终明确 `browser_records_backed_up: false`，不会冒称已替用户导出。

需要恢复界面时使用回执中的旧 HTML 覆盖回原路径，先确认没有后续页面改动。不要通过打开备份目录里的 HTML 判断原浏览器记录是否丢失。

## 版本与日常刷新

`data-ui-revision` 和独立 `workbench-shell-sha256` 描述界面，`workbench-data.system.suite_version` 描述生成数据的工具版本。前者不放入训练数据块。模板改动后必须重新计算规范化指纹，并在发布时更新界面版本与历史识别清单；指纹归一化只忽略约定的用户配置和数据。

现有 `upgrade` 明确输出 `CONFIG_ONLY`；尚需界面升级或存在托管文件冲突时返回退出码 2。不能把它包装成整套升级成功。`doctor` 输出 UI 状态与运行模板位置，界面异常时报告 `NEEDS_UI_ATTENTION` 并返回退出码 2。完整 checker 仍独立检查数据是否最新，不能把纯界面升级成功当作 `formal_refreshed`。

## 页面行为与验收

五个全局入口直接存在于模板中，由独立脚本切换一级区域。JSON 解析失败、业务脚本语法异常及受控渲染错误不能清空导航；出现失败时提供可见提示。桌面饮食页面保留侧栏，未保存餐食编辑离开前可取消。手机饮食页面保留专用返回入口；训练录入和真正的全屏弹窗保留专注模式与返回流程。

回归包括 Python 迁移安全测试、历史版本识别、数据逐字节保留、背景配置、未知改动拒绝、失败回滚、并发编辑、直接打开 HTML 后的 IndexedDB 记录和照片保留，以及 375/899/900/1440 像素导航行为。发布前还必须通过完整套件、浏览器与隔离安装验证；本地通过不等于已安装同步、发布或上线。
