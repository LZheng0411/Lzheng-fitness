# 视觉契约

工作台唯一视图资产为 `../assets/workbench-template.html`，模板版本为 `lzheng-fitness-workbench-v3`。AI 只生成或刷新 `workbench-data`，不得改写模板导航、组件和视觉。跨页面职责见 `../../lzheng-training-system/references/html-template-contract.md`。

## 固定语言

- 黑、白、灰为主，不依赖彩色表达状态。
- 全局背景、Hero 和桌面侧栏共享同一组图片资产，但各自使用不同遮罩与取景。
- 全页使用与已批准个人 HTML 相同的深色透明表面，Hero、正文、导航和弹层透出同一背景；不再叠加另一套暖白卡片或独立背景。
- 桌面为左侧六入口：今日、训练、饮食、进展、知识库、设置；手机为前五项底栏与本页目录。趋势、设置和指南保留相应次级入口。
- 独立的静态导航继续作为初始化失败时的兜底；正常页面使用共享的手机/桌面展示层，路由仍由原业务引擎执行。桌面饮食页面保留侧栏；手机饮食、训练录入与全屏弹窗使用专用返回入口。未保存餐食编辑离开前允许取消。界面版本、升级和异常降级见 [界面升级](ui-upgrade.md)。
- 必须使用 Skill 内置的项目视觉资产；视频不可播放、用户开启减少动态效果或资源缺失时，自动退回静态背景。正式 HTML 和发布副本均使用本地相对路径，不使用外链。
- 已生成工作台的用户壁纸只能通过 `Replace-FitnessWorkbenchBackground.py` 替换；图片必填、MP4 可选，操作前备份并在完成后运行工作台检查。具体流程见 [壁纸替换](background-replacement.md)。

## 信息层级

1. 今天练什么或恢复什么；
2. 精确重量、组次、RPE/RIR 与完成标准；
3. 周期位置和下一验证点；
4. 负荷趋势与近期复盘；
5. 数据同步、规则和使用说明。

当动作处于重量校准状态时，优先显示“从轻重量试组 → 小幅增加 → 记录重量、次数、余力和动作质量”的操作引导；不能把待校准误写成正式处方。

不要把所有信息做成同一种纯文本白卡。计划、训练日、趋势、复盘和同步状态使用不同组件结构。

## 图表

- 已执行：深色实线和实心点；
- 后续计划：灰色虚线和空心点；
- 实际与计划重合：只保留实线；
- 数值标签必须保持字体比例，禁止横向压扁；
- 绘图区可透视背景，但需要网格、边界和对比度保证可读。

## 响应式

- 375px：单列、无横向滚动、底部导航可触达；
- 760px 及以下采用手机展示层；761px 起采用桌面展示层；趋势和复盘按内容空间布局；
- 1440px：内容区约 1180px，趋势双列，侧栏不挤压正文；
- 动态长文本必须换行，重量和组次不得被截断。
