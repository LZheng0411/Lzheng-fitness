# Lzheng—力量训练复盘

把一次训练放回可验证的推进路径。优先遵守明确周期；没有周期时使用滚动渐进；数据不足时先建立基准。任何模式都必须让用户知道本次表现、下一次具体怎么练、判断依据和需要继续记录什么。

## 必读上下文

- 动态训练事实：用户直接提供的完整当次记录优先级最高；用户授权且当前环境可访问外部训练记录时再查询最近记录、恢复信息和体重。
- 周期处方：读取用户明确指定的当前计划；未指定时依次检查 `LZHENG_FITNESS_HOME/plans/` 和当前工作目录的 `lzheng-fitness-output/plans/`。不要把历史 HTML 或保留副本当作当前处方。
- 周期调整：需要审核或修改多周计划时，读取 [Lzheng 周期调整规则](references/lzheng-cycle-adjustment-rules.md)。即使没有安装周期规划 Skill，本 Skill 也必须能够完成调整判断。
- 无周期推进：进入滚动或基准模式时，读取 [无周期滚动复盘规则](references/rolling-review-rules.md)。
- 输出与沉淀：读取 [复盘输出规范](references/review-output-spec.md) 和 [本地记录规范](references/local-review-record-spec.md)。
- 证据边界：读取 [证据基础](references/evidence-base.md)。

## 模式选择

按以下顺序选择且只选择一种模式：

1. **周期模式 `cycle`**：存在当前有效计划，并能核验计划版本、Wn、训练日和动作职责。
2. **滚动渐进模式 `rolling`**：没有当前有效周期，且至少存在两次可比训练；若用户明确提供渐进方式，先审核后决定沿用或纠正。
3. **基准训练模式 `baseline`**：没有当前有效周期，且只有一次或没有可靠可比记录。

如果发现疑似存在周期，但计划版本、周次或训练职责无法对应，先提出最少量澄清问题；不得为了给出答案而擅自切换到滚动模式。

## 权限边界

- 每次完成复盘后写入可移植的本地 Markdown 复盘记录并更新索引。用户指定目录优先；否则使用 `LZHENG_FITNESS_HOME/reviews/`，未设置时使用当前工作目录的 `lzheng-fitness-output/reviews/`。
- 不得编造、补全或篡改外部原始训练记录；默认不写回外部服务。
- 周期模式中，改变周次、动作、重量、次数、组数、RPE 路径、测试目标或后续周期，先给完整待确认方案；确认后创建新的 `-vNN.html`，不得覆盖旧版本。
- 滚动模式中，可以直接给出下一次的小幅调整：一次只改变重量、次数或组数中的一个主要变量；加重不超过最小加重单位，减重通常为 2.5%—7.5%，或减少 1 组。
- 创建多周周期、改变每周频率、训练日结构、动作体系或测试目标，仍需先确认。
- 基准模式可以直接给出 RPE 选重的校准训练，但数据不足时不得编造精确公斤数。

## 通用复盘流程

### 1. 核验训练事实

确认训练日期、动作与器械、重量单位、正式组次数、逐组 RPE/RIR、动作标准、疼痛、休息和异常疲劳。负重自重动作必须记录当天体重。

会改变判断且无法推断的字段缺失时，只输出已知事实、保守基准和待补项，不给无依据的精确推进。

### 2. 确定判断依据

- 周期模式：定位计划版本、Wn、训练日、有效暴露序号及动作职责。
- 滚动模式：读取最近 2—4 次同动作、同器械、同动作标准记录，明确用户当前渐进方式及其适用性。
- 基准模式：说明缺少哪些可比数据，并选择对应动作的校准处方。

### 3. 逐动作判定

比较重量、组数、次数、休息、动作标准和逐组 RPE。两组及以上正式工作组按 `首组 RPE→末组 RPE` 判定；历史事实必须列逐组实际 RPE 或明确末组 RPE。

不要用首组偏轻、末组正常变难或一次状态差判断方案失效。多个动作独立推进，不能因为一个主项偏轻就让整堂训练同时加码。

### 4. 评估恢复与安全

结合睡眠、疼痛、异常疲劳、体重、大肌群暴露间隔和辅助动作强度判断。锐痛、麻木、放射痛或持续加重的关节痛时，停止该动作的高强度推进，不提供硬顶方案。

### 5. 生成下一次处方

- 周期模式：直接引用当前计划的下一次处方，或提出覆盖完整周期后果的待确认调整。
- 滚动模式：按用户适用的渐进方式或默认滚动规则，直接给重量、组次、RPE 路径和执行条件。
- 基准模式：按动作类别给 RPE 校准训练；只有一条可靠记录时优先重复，建立第二个可比样本。

### 6. 沉淀复盘

按照本地记录规范创建或修订一个 Markdown 文件，并更新输出目录中的 `INDEX.md`。同一来源不得重复建档；写入后重新读取记录和索引验证。

## 周期模式调整要求

只有连续两次同重量掉次数、同组次 RPE 上升约 1 级、技术持续恶化、恢复信号恶化、原处方起点明显不成立，或目标/训练日发生变化时，才优先判断为周期问题。

周期调整方案必须写清：触发证据、当前与建议路径、下一次处方、后续周次和容量变化、验证周及目标的处理、需要用户确认的具体变更。

## 固定输出

严格按输出规范依次给出：

1. `复盘模式与依据`；周期模式同时写清周期位置。
2. `本次判定`。
3. `恢复与干扰`。
4. `渐进方式检查`；滚动/基准模式必写，周期模式仅在相关时写。
5. `下一次训练`。
6. `待确认周期调整`或`待确认结构调整`；无需确认时写明当前处理。
7. `待补全记录`；无缺失时写“无”。
8. `已沉淀`。

## 质量检查

- 没有伪造 Wn、计划版本、训练日或体重；
- 疑似存在周期但无法对应时没有擅自进入滚动模式；
- 滚动模式使用了最近 2—4 次可比记录，并检查用户现有渐进方式；
- 每次滚动推进只改变一个主要变量；
- 数据不足时给的是 RPE 校准，不是虚构公斤数；
- 多组动作使用逐组实际 RPE 或 `首组→末组` 处方；
- 一次异常没有被误判为长期问题；
- 下一次训练包含明确重量或选重规则、组次、RPE 和执行条件；
- 本地记录和索引已保存并验证；
- 未经确认没有创建周期、重构训练安排或修改外部训练记录。
