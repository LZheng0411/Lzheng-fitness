# HTML 输出规范

## 内容顺序

页面采用“固定计划说明 + 完整处方”：

1. 页头：计划名、状态快照时间、整体阶段、阶段目标；
2. 概览：阶段目标、周期、频率、阶段和目标类型；
3. 本周：必练、可选和恢复结构；每张卡补充训练重点与预计时长；
4. 训练日：每个训练日一张简表卡，桌面并排、手机单列；只显示动作、组次和目标，完整负荷校准、动作理由与短版默认折叠；
5. 进阶：用一张表合并渐进规则、AI 主动确认的复盘节点和已启用的单项周期引用；周期末在确认用户实际反馈后生成下一阶段计划；
6. 覆盖：可切换查看动作模式周组数，以及健美肌群的直接组、间接折算、合计和全部来源；只显示合计大于 0 的实际覆盖项。

计划页不展示“今天/下一次训练”、完成按钮或实时记录；这些只属于工作台。不要在第一屏堆理论、长表和来源列表。未启用周期时不显示空周期区。

## 视觉和交互

- 黑白灰、细分隔线和浅灰表头；导航、按钮、状态、表格均不得使用绿色；
- 禁止渐变、多色仪表盘和厚重卡片；
- 默认读取本 Skill 的 `assets/header-lineart.png` 并转 Base64，以低对比、低不透明度显示；找不到时使用纯文字页头；
- 训练日简表使用三列：动作、组次、目标；标准计划直接可见，重量说明和 30/20/10 分钟版本按需展开；
- 关闭 JavaScript 时仍展示两张训练日标准简表；打印时展开训练日说明并同时显示两种覆盖视图；
- 手机端单列、隐藏装饰图；长表允许横向滚动；390px 视口下页面的 `scrollWidth` 不得大于 `clientWidth`，只有导航、周计划卡片或长表等明确容器可以内部横向滚动；
- 一级导航固定为 `概览｜本周｜训练日｜进阶｜覆盖`，必须使用固定定位并在滚动到页面任意位置时保持可用；不得加入分层、来源、假设或安全规则。
- 提供 `scroll-margin-top`，固定导航不能挡标题。
- 每个动作必须显示已核验工作重量与下一次规则，或显示逐步校准引导；禁止只留下“自行选择重量”。

## 技术边界

- 单个 UTF-8 HTML；
- CSS 和少量交互脚本全部内嵌；
- 不使用 CDN、网络字体、外部脚本、iframe 或远程图片；
- 外部官方来源可以作为普通超链接，但页面显示不依赖网络；
- 所有用户文本先 HTML 转义；
- 页面写入 `data-plan-id` 和 `data-snapshot-id` 便于审计；
- 生成器拒绝覆盖已有文件。

## 运行

```powershell
python scripts/validate_plan.py <plan.json>
python scripts/render_fitness_plan.py <plan.json> <output.html>
python scripts/audit_html_plan.py <output.html> --plan <plan.json>
```

交付前在宽屏、窄屏和打印样式检查：标题、按钮、动作卡、长文本、中文换行和来源列表均可读。
